# 图片处理管线

## 流程

```
File → 校验/EXIF 摆正 → ImageBitmap
                            ├─ 副本 → Worker（检测）
                            └─ 原件 → 预览画布 / 导出
```

**关键点**：传给 Worker 的必须是 `bitmap` 的**副本**。`ImageBitmap` 一旦作为 transferable 交给 Worker 就会 detached，主线程再用它会抛 `The image source is detached`，画布全黑。

## 导入

| 检查 | 行为 |
|---|---|
| 格式 | 只接受 JPEG / PNG / WebP，其他拒绝且**不破坏当前素材** |
| 空文件 | 拒绝 |
| 解码失败 | 提示「文件可能已损坏」 |
| EXIF Orientation | 按 1–8 正确摆正，预览与导出方向一致 |
| > 4000 万像素 | 先询问用户，确认后才处理 |

EXIF 解析直接读取 JPEG 的 APP1 段（支持大小端），不引入第三方库。

## 遮挡形状

**为什么不能只用检测框**：检测框通常只包住脸颊，不包含额头与下巴，直接用会「露下巴 / 露额头」。

实现（`render/mask-shape.ts`）：

- 用 5 个关键点估算面部主轴（两眼连线）→ 遮罩随头部倾斜旋转；
- 默认**圆角矩形**（侧脸时四角不露脸颊），可切换**椭圆**（更自然）；
- 外扩：水平 12%、垂直 18%、**向上额外 10%**（覆盖额头）。

关键点异常（缺失、NaN、两眼重合）时自动退回轴对齐矩形，不崩溃。

## 遮挡样式

| 样式 | 实现 | 参数 |
|---|---|---|
| 高斯模糊 | 多轮「缩小一半再重采样」，最后放大回原区域 | 半径按短边比例 |
| 马赛克 | 降采样到 `短边×(3%~12%)` 的块，再关掉平滑放大 | 块大小按短边比例 |
| 实心 | 直接填充颜色 | 颜色、不透明度 |

### 模糊为什么要多轮缩小

单轮降采样在大半径下**仍能辨认五官轮廓**，对隐私工具不可接受。实测对比：

- 单轮：脸型、眼睛位置、口鼻轮廓均可见；
- 多轮（每轮再缩小一半）：只剩模糊色块，**完全不可辨认**。

轮数随半径增加（1–3 轮），这是刻意的：隐私工具的「默认值必须足够安全」。

### 跨分辨率一致性

模糊半径与马赛克块大小**全部按素材短边比例计算**：

```
radius = clamp(shortSide × 0.02 × (0.5 + strength × 1.5), 8, 80)
block  = max(4, shortSide × (0.03 + strength × 0.09))
```

因此 50% 预览与 100% 导出看到的遮挡强度一致——不会出现「预览糊了、导出没糊透」的问题。

## 预览

- 预览画布最大边长 1600px（超大图等比缩小），避免拖慢绘制；
- 参数变化 **80ms 防抖 + requestAnimationFrame** 重绘；
- **调整参数不重新检测**——检测只在导入时做一次；
- 按住「对比原图」按钮临时显示未遮挡版本。

> 踩坑记录：canvas 的 `width`/`height` 属性必须先于首次绘制设置好，否则会以默认 300×150 渲染，导致遮挡画在错误坐标。实现里在 `nextTick` 之后统一 `syncCanvasSize()`。

## 导出

- 使用**素材原始分辨率**；
- 格式 JPEG / PNG / WebP，可调质量（默认 0.92）；
- 文件名 `原名-blurred.扩展名`，**不覆盖原文件**；
- 非 PNG 格式先铺白底，避免透明区域变黑。

## 逐脸开关

每张脸有独立 id 与 `enabled` 标志，`buildMasks` 只对启用的脸生成遮罩。
支持「全部」「全不选」批量操作。

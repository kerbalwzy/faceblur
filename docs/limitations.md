# 已知限制

本文记录**实测**得出的限制，不是猜测。数据来自 `tests/e2e/acceptance` 的自动化验收（Chromium / macOS / Apple Silicon）。

## 检测能力边界

### 能可靠检出的

| 场景 | 样本 | 检出 | 置信度 |
|---|---|---|---|
| 标准正脸 | 512×512 | 1 张 | 88% |
| 多人合影 | 768×256（3 人） | 3 张 | 84/81/73% |
| 竖构图 | 1080×1920 | 1 张 | 87% |
| 逆光/低对比 | 512×512 | 1 张 | 83% |
| 极暗 | 512×512 | 1 张 | 71% |
| 带 EXIF 方向 | 1080×1080 | 1 张 | 88% |
| 小尺寸原图 | 90×90 | 1 张 | 86% |

### 检出不了的

**极小脸（占画面比例过小）**

样本：800×600 的画布中放一张 90×90 的缩略图（人脸约 30px，占整图 0.4%）。

| 档位 | 结果 |
|---|---|
| 320 标准（阈值 0.6） | 0 张 |
| 320 低阈值 0.2 | 0 张 |
| 640 高精度（阈值 0.35） | 0 张 |
| 640 极低阈值 0.1 | 0 张 |

**原因**：图整体被等比缩放后，人脸只剩约 12px，低于模型可分辨的尺度。
**为什么两阶段重检救不了**：重检只对「首轮已检出但尺寸偏小」的人脸生效，首轮完全漏掉时无从补救。

**缓解方式**：把这类照片先裁剪到人脸附近再处理，或使用分辨率更高的原图。

### 其他已知边界

- 侧脸超过约 75°、严重遮挡（口罩+帽子+墨镜）、纯剪影会漏检；
- 极小脸需要手动补画（本版未提供手动补画功能）；
- 检测阈值调高可减少误检，但会增加漏检——这是双向取舍。

## 精度的真实表现

| 档位 | 检测尺寸 | 阈值 | 320 单帧耗时 | 适用 |
|---|---|---|---|---|
| 标准 | 320 | 0.6 | ~4–14 ms | 默认，绝大多数场景 |
| 高精度 | 640 | **0.35** | ~10–40 ms | 小脸、多人、需要更准的场合 |
| 视频 | 320（固定） | 0.6 | ~4–10 ms/帧 | 逐帧处理，不提档 |

**为什么高精度档阈值更低**：实测发现提高分辨率后，画面边缘的小脸置信度会**下降**（768×256 拼图中，左侧人脸在 320 输入下得 0.73，640 输入下只得 0.56）。若保持 0.6，高精度档会比标准档检出更少——与用户预期相反。因此高精度档采用「更高分辨率 + 更宽松阈值」，保证检出**只多不少**。

## 性能实测

复现方式：

```bash
npm run build
npm run preview -- --port 4175 &
npm run benchmark -- --url http://127.0.0.1:4175
```

### 测试机 A：Apple Silicon Mac（8 核，多线程 4 threads，生产构建）

| 项目 | 耗时 |
|---|---|
| 图片（512×512）导入 → 检出完成（含引擎初始化） | 824 ms |
| 图片导出 | 89 ms |
| 视频（512×512 / 2 秒 / 60 帧）完整处理 | 2112 ms |
| **视频处理倍率（相对 2 秒素材）** | **1.06×** |

单帧检测（多次取中位数，开发模式下）：
320 输入 11 ms · 480 输入 13 ms · 640 输入 19 ms。

**未在低端设备上实测**。设计文档 D14 的基线（4 核 CPU / 8 GB 内存）仍是估算值。
请在目标设备上运行 `npm run benchmark` 并把结果追加到 `docs/benchmark-latest.md`。

## 功能缺口

| 缺口 | 影响 | 状态 |
|---|---|---|
| **视频导出无音轨** | 导出结果没有声音 | 已知未实现，需 decode → AudioEncoder → muxer 全链路 |
| 无手动补画 | 漏检的人脸无法手动遮挡 | 接口已预留位置 |
| 无批量图片 | 一次只能处理一张 | 设计已预留 `File[]` |
| 视频固定 30fps 输出 | 高帧率素材会被降帧 | 打码场景可接受 |

## 浏览器兼容

| 能力 | Chrome | Safari | Firefox |
|---|---|---|---|
| 人脸检测（WASM SIMD） | 91+ ✅ | 16.4+ ✅ | 89+ ✅ |
| 视频导出（WebCodecs） | 94+ ✅ | 16.4+ ✅ | 受限（走降级） |
| 多线程推理 | 需 COOP/COEP | 需 COOP/COEP | 需 COOP/COEP |

不支持 WASM SIMD 的浏览器会直接禁用处理功能并给出升级提示，不会静默失败。

## 已知的体验问题

- **首次加载约 3.8 MB**（gzip 后）：ORT 运行时 13.6 MB 未压缩 + 模型 224 KB。慢网络下首次使用需要等待。
- **视频处理占用主线程较久**：虽然推理在 Worker，但逐帧解码与绘制仍在主线程，处理期间界面会变慢（不影响取消）。
